# MathResearch Ledger v1.5.0

Released 2026-11-03. Core/MCP additive capabilities and semantic convergence,
following the v1.4.0 DSH Host activation release. See the
[design record](../design-convergence-2026-11-03.md) for rationale.

## Primary target binding

`research_update_problem` formally supports `primary_claim_id` for an exact existing
Claim in the same Problem, including provisional/unverified Claims. Designation
requires `revision_kind="semantic"` and uses existing versions, snapshots and
pinned-dependency freshness. TEXT_ONLY is valid. Binding does not confer verification
or acceptance, and binding alone preserves statement authority. Actual statement or
primary-target text changes reset statement authority to PROVISIONAL.
The designation-only CLI is `ledger update-problem PROBLEM CLAIM`, with semantic
revision fixed internally; optional zero-write preview and expected-version pins remain.

## Problem lifecycle convergence

`lifecycle_status` is the sole current project lifecycle state. Legacy
`ProblemRecord.status` remains only for disk/hash compatibility. Status distinguishes
`primary_target_statement`, `primary_target_binding = TEXT_ONLY | CLAIM` and
`primary_claim_id`, with navigation when bound. Lifecycle remains independent of
mathematical authority. Historical data is not rewritten.

## Review context

ReviewPacket includes the Problem ref/version, statement, primary-target text and
binding in its mathematical context and packet version. Lifecycle, closure, title,
summary and ordinary metadata do not participate in that mathematical review version.
New report submissions must pin the expanded current packet; historical reports
remain intact. Review stays advisory, exact-target and complete-or-error within the
64 KiB MCP output bound.

## Search

`research_search.kind` is a finite enum of the 24 kinds reachable through production
search, shared with server-side validation. Unknown kinds fail fast. A valid filter
strictly combines with `problem_id`; an exact identity excluded by kind returns no
hits without lexical fallback. Prefer `problem_id + kind` for a specific object type.
Ranking adds a deterministic title boost without embedding, rewriting or reranking.

## Stale report

Reports explicitly identify workspace or Problem scope and set
`counts_are_scoped=true`. Object, verification and acceptance counts refer to that
scope, without implying workspace-wide totals. Freshness rules are unchanged.

## Compatibility and artifacts

The MCP tool count remains eleven. Additive input schema changes are
`research_search.kind` and `research_update_problem.primary_claim_id`; additive
output fields are `research_review_packet.problem_context` and
`research_stale_report.scope` / `counts_are_scoped`. All eleven public MCP input
schema digests are pinned by contract tests.

No historical Problem membership, object IDs, provenance, versions or receipts are
migrated. Old external review packets require regeneration before a new report
submission. Runtime, Host plugin, fallback Bundle and compatibility manifests are
aligned at 1.5.0; the Host activation implementation is unchanged. Updating source or
downloading artifacts does not upgrade an installed runtime or Profile.

The GitHub Release contains the Python wheel/sdist, Host/fallback package tarballs
and SHA256SUMS. No PyPI/npm registry publication or local installation is performed.

## Release verification boundary

Code-level release results: **337 passed** — 264 Core/CLI/schema/context tests,
70 MCP scope/stdio/verification tests and 3 public-package contracts. Ruff
check/format, mypy (96 source files), build and diff checks passed. The first
restricted build hit a Windows temporary-directory permission error; the approved
build succeeded. All four public archives were inspected for private state,
rendered runtime paths, caches and logs.

Synthetic Core/MCP/schema/CLI and package contracts, Ruff check/format, mypy,
standard wheel/sdist build, archive inspection and `git diff --check` are the
verification scope for this release. Full pytest and the actual DSH release gate
are not invoked; prior Host results are historical, not v1.5.0 acceptance evidence.
No DSH Host/runtime/Profile/live-plugin acceptance, real Ledger access or research
task is performed. DSH live acceptance was intentionally not performed and is left
for post-release real use.
