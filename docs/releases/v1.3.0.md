# MathResearch Ledger 1.3.0

Prepared **2026-10-31**. **Protocol-neutral, DSH-first, other Harnesses on demand.**
This release consolidates the DSH-first support policy and release process while
preserving MathResearch Ledger as the product name and a standard MCP server as
the integration boundary. The official Host UI name is **MathResearch Ledger for
DSH**; this does not rename Core or introduce a DSH-only protocol.

## Support commitments

| Tier | Harness | Commitment |
|---|---|---|
| 1 — Official | DeepSeek Harness | Primary installation path; actively developed, documented and regression-tested; actual DSH Host acceptance is release-blocking with Core and MCP |
| 2 — Compatibility | Codex | Retained best-effort; not every feature gets dedicated Harness regression; Codex-only issues normally do not block unless shared Core/MCP semantics are affected |
| 3 — On demand | Other Harnesses | Standard MCP remains available; add a dedicated adapter only for a real use case |

The shared deterministic services, MCP schemas and errors, exact workspace binding,
provisional-write enforcement and human-authority boundary remain Harness-neutral.
The eleven MCP tools are retained. **No Core/MCP breaking change or research-schema
migration is introduced by 1.3.0.** Historical records, versions and absolute
provenance must not be rewritten during a tool upgrade. Existing legacy-format
migration rules are unchanged; this release is not a corpus migration command.

## Official Host package and manual fallback

The [Agent Host plugin](../../integrations/deepseek-harness/host-plugin/README.md),
displayed as **MathResearch Ledger for DSH**, is the only recommended/default DSH
installation. It uses the official MCP client inside each Agent's scope, binds to
the immutable persisted session root and awaits tool readiness before Agent creation
returns. The stable package ID is `dsh-math-research-ledger-host`.

English and Chinese locales are added for the official Host title. The public Host
npm tarball therefore contains **seven files**:

```text
index.cjs
package.json
cordis.patch.yml
README.md
LICENSE
locale/en.json
locale/zh.json
```

The five-file tarball in dated 1.2.2 acceptance was the earlier layout, not the
1.3.0 package contract. Public packages must contain no rendered runtime paths,
local Profile configuration, research data or private acceptance evidence.

The config-only Bundle remains **Fallback / manual single-workspace integration**,
not a second official/default install. Its stable package ID, MCP server name and
configuration-only behavior are retained. The alternatives are mutually exclusive
in one Profile: remove the old package through normal DSH commands before adding
the chosen one. OFF does not remove an installed package's UI candidate. Do not
manually rewrite Profile files or run both packages together. See the
[installation and migration guide](../../integrations/deepseek-harness/README.md).

## Upgrade without migrating research

1. Finish publication of the reviewed 1.3.0 assets before migrating a real Desktop
   deployment; a documentation change is not an installed upgrade.
2. Stop sessions using the runtime to be replaced. Install the matching 1.3.0 wheel
   with `[mcp]` into a persistent runtime outside research state and disposable output.
3. Prepare a new Host package, remove the old fallback or old Host installation as
   applicable, and add the new package through the normal Desktop-installed `dsh`
   command in ordinary PowerShell. Keep rollback backups private.
4. Reload/restart the Host, then create/resume a new Agent at the intended initialized
   research root. Verify one exact eleven-tool set, reported root and scoped reads.
   Installation never initializes or migrates Ledger state. Existing Agents are not
   retrofitted by ON; OFF affects new Agents while existing clients last until disposal.
5. Perform real-workspace validation only within its separately authorized scope.
   Read-only status/search acceptance is not authorization for mutations or a claim
   of GUI conversational validation.

Standalone standard MCP clients remain supported by the shared contract; users
needing Codex can follow the [Tier 2 compatibility guide](../codex-mcp.md).

## Release gate and verification status

The required gate is **Core + standard MCP + actual DSH Host acceptance**. Hosted CI
covers shared checks and DSH packaging, not the actual installed Host. The manual
self-hosted DSH workflow and local release runner require matching official DSH
runtime paths and fail when actual Host prerequisites/evidence are missing. Codex
packaging compatibility is recorded separately and is normally non-blocking; shared
semantic failures remain blocking regardless of where they are discovered. See
[development and release gates](../development.md).

Local verification completed on **2026-10-31** against the 1.3.0 release tree:

- Unfiltered full suite: **657 passed, 1 skipped** (831.55 seconds).
- Required Core/MCP/DSH gate: **655 passed, 1 skipped, 2 deselected**
  (770.31 seconds); the two separate Codex packaging compatibility cases **passed**.
- Actual Windows **DSH 0.2.1-rc.3** Host acceptance: **17 scenarios passed**, with
  synthetic workspaces and no model call. This is actual Host/Agent-factory
  acceptance, not GUI conversational acceptance or a real Desktop migration.
- Focused packaging/release checks: **30 passed, 1 integration case deselected**.
- Ruff lint and format (**144 files**), mypy (**96 source files**), Python build
  and `git diff --check` passed. The release runner recorded every required check
  successful; optional real-workspace read-only acceptance was not enabled.

Hosted CI and GitHub publication are separate from these local results. Their
commit-specific outcome and final artifact checksums are recorded on the GitHub
Release only after completion. These checks do not claim an installed Desktop
upgrade, GUI migration or native Codex app-server smoke.

The [redacted 2026-10-30 DSH-first closeout](../dsh-first-finalization.md) preserves
successful earlier checks on a **1.2.2 checkout**: 657 passed / 1 skipped in the
unfiltered full suite; 655 passed / 1 skipped with two compatibility cases run
separately and passed; 18 actual Host scenarios; and a separate installed-wheel
17-scenario Host check. These are historical observations, not the new 1.3.0 gate.
The earlier authorized real-workspace reads left the Ledger unchanged; exact private
inventories, process identifiers and local diagnostic/evidence links are omitted
from public documentation.

## Known boundaries

Historical Host evidence is Windows **DSH 0.2.1-rc.3** specific. GUI conversational
acceptance, macOS/Linux Host behavior, UNC/network roots, real-corpus mutations and
rc.2 acceptance of the Agent Host adapter remain unverified. The native Codex
app-server smoke was not rerun for the 2026-10-30 support-policy closeout; its older
evidence keeps its own date and versions. The release does not repair permissions,
change authentication/Full Access, add an Agent loop or expose human acceptance to
model-callable tools.
