# MathResearch Ledger v1.5.2

Released on GitHub on 2026-11-27. This patch prepares public npm/PyPI distribution
and native DSH Host version checks. **Availability on GitHub does not mean the
packages are published to npm or PyPI.** Registry publication is a separate step.

## Host and Python runtime

- The `dsh-math-research-ledger-host` bundle now has public npm metadata and
  bounded DSH and Schemastery peer ranges. After npm publication, install it by
  its package name in DSH Plugins. Link or local `.tgz` users must remove the old
  Host and install by registry package name once to receive native updates.
- The Host accepts stable Ledger **1.5.x** with `[mcp]` on Python **3.11+**. It
  reports an actionable error for incompatible versions. An already-compatible
  runtime does not need to be reinstalled to match the Host patch version. DSH
  updates the Host only; users manage the Python environment with its own `pip`.
- Agent workspace binding, the relative activation pointer, all eleven MCP tools,
  and research data and authority semantics are unchanged. No data migration is needed.

## GitHub installation

Before registry publication, or for offline installation, download the Host
`.tgz` and Python wheel from this release. Install the Host tarball via DSH
Plugins (not the fallback tarball) and the wheel with `[mcp]` in the intended
Python environment if one is needed. Keep the existing valid activation pointer.
See the [Host installation guide](https://github.com/Caie777/math-research-ledger/blob/v1.5.2/integrations/deepseek-harness/host-plugin/README.md).

## Assets and verification

Includes the wheel, sdist, Host and fallback `.tgz` bundles, and `SHA256SUMS`.
The published files are the input to the manual registry workflow: `verify-only`
checks the release without uploading to a registry. For subsequent publication,
PyPI must expose both matching distributions before the npm workflow can publish.

This release reuses the prior targeted Host/runtime checks. Release preparation
is limited to building and verifying the archives and running the GitHub workflow
in `verify-only` mode. No full pytest, DSH live acceptance, or real Ledger access.
