# MathResearch Ledger 1.4.0

Prepared **2026-11-03**. This is a **DSH Host activation** release: the Host plugin may
stay globally ON, but research tools are mounted only for a workspace that explicitly
enables Ledger. Core research semantics, the eleven MCP tool contracts and Research
Episode semantics are unchanged.

## Workspace-gated activation

- A new Agent in an ordinary workspace gets **0 Ledger tools**, starts **no Python MCP
  process** and creates **no research state**. There is no workspace scan, no ancestor
  lookup and no implicit initialization.
- The Host reads exactly one tiny pointer in the exact session root,
  `.math-research-ledger-link`. It contains the Ledger state directory relative to that
  root, for example `.math-research-ledger` or `research/foo/.math-research-ledger`.
- A valid pointer mounts one scoped MCP client bound to that Ledger and exposes exactly
  eleven tools. A malformed or escaping pointer fails closed with a clear error; it never
  falls back to another directory. One session root binds at most one Ledger.
- Activation uses the DSH native human command, not a resident model-facing bootstrap
  tool:

```text
/math-research-ledger enable [workspace-relative directory]
```

The command initializes the default `./.math-research-ledger` or the requested in-root
directory through the normal `math_research` CLI, then waits for MCP readiness before
reporting success. `..`, absolute paths outside the exact session root, and
symlink/junction escapes are rejected.

Existing workspaces receive only a pointer; their Ledger data is not moved, migrated or
rewritten.

## Problem identity

- An unknown Problem now reports **existing Problems by name** (`Existing Problems: …`)
  instead of a numeric range that read like an ID allowlist. The check remains an
  existence check over real dossiers on disk; Problem numbers carry no semantic meaning.
- `research_update_problem` no longer rejects a non-canonical ID shape before the
  existence check. New Problems are still created only through
  `research_create_problem`.

## Packaging

- Host package `dsh-math-research-ledger-host@1.4.0` adds `activation.cjs` to the public
  tarball (eight files total). Its declared DSH range is `0.2.x`.
- The Python Ledger runtime is unchanged at **1.3.0** and is not reinstalled by this
  Host-only release. A future Python build will carry the Problem-message source change.

## Verification

Lightweight, scoped checks only — no full release gate or lifecycle matrix:

- Targeted pytest: Host packaging contracts and Problem lifecycle (including the dynamic
  existing-Problem report); Node path tests: 27 tests, 24 passed, 3 skipped where Windows
  cannot create ordinary symlinks.
- Ruff lint/format and `git diff --check`.
- Host packaging: eight-file tarball, `0.2.x` ranges, unrendered Python placeholder.
- Actual DSH 0.2.1-rc.5 smoke through the official services/factory: ordinary workspace
  **0 tools / 0 processes / no state**; explicitly enabled default and subdirectory
  workspaces **11 tools** with correct binding; out-of-root and unknown commands rejected
  without side effects; parent Ledger not inherited; real `D:\Math Research` pointer
  returns **11 tools** with working `research_status` and unchanged Ledger inventory.

Unverified boundaries: no macOS/Linux DSH, no live GUI conversational turn, and no real
research mutation. The Problem-message change is committed but not installed into the
local 1.3.0 runtime.
